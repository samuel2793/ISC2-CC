# Puertos seguros

Algunos protocolos de red transmiten informacion en texto claro, lo que significa que no esta cifrada y no debe usarse. La informacion en texto claro esta sujeta a sniffing de red. Esta tactica usa software para inspeccionar paquetes de datos mientras viajan por la red y extraer texto como nombres de usuario y contrasenas.

El sniffing de red tambien podria revelar el contenido de documentos y otros archivos si se envian mediante protocolos inseguros. La tabla siguiente muestra algunos de los protocolos inseguros junto con alternativas seguras recomendadas.

### 21-FTP

**Puerto inseguro:** 21-FTP

**Descripcion:** El puerto 21, File Transfer Protocol (FTP), envia el nombre de usuario y la contrasena usando texto plano desde el cliente al servidor. Esto podria ser interceptado por un atacante y luego usado para recuperar informacion confidencial del servidor. La alternativa segura, SFTP, en el puerto 22 usa cifrado para proteger las credenciales del usuario y los paquetes de datos que se transfieren.

**Protocolo:** File Transfer Protocol

**Puerto alternativo seguro:** 22*-SFTP

**Protocolo:** Secure File Transfer Protocol

### 23-Telnet

**Puerto inseguro:** 23-Telnet

**Descripcion:** El puerto 23, telnet, es usado por muchos sistemas Linux y otros sistemas como una terminal basica basada en texto. Toda la informacion hacia y desde el host en una conexion telnet se envia en texto plano y puede ser interceptada por un atacante. Esto incluye nombre de usuario y contrasena, asi como toda la informacion presentada en pantalla, ya que esta interfaz es completamente textual. Secure Shell (SSH) en el puerto 22 usa cifrado para asegurar que el trafico entre el host y la terminal no se envie en formato de texto plano.

**Protocolo:** Telnet

**Puerto alternativo seguro:** 22*-SSH

**Protocolo:** Secure Shell

### 25-SMTP

**Puerto inseguro:** 25-SMTP

**Descripcion:** El puerto 25, Simple Mail Transfer Protocol (SMTP), es el puerto no cifrado predeterminado para enviar mensajes de correo electronico. Como no esta cifrado, los datos contenidos en los correos podrian descubrirse mediante sniffing de red. La alternativa segura es usar el puerto 587 para SMTP con Transport Layer Security (TLS), que cifrara los datos entre el cliente de correo y el servidor de correo.

**Protocolo:** Simple Mail Transfer Protocol

**Puerto alternativo seguro:** 587-SMTP

**Protocolo:** SMTP con TLS

### 37-Time

**Puerto inseguro:** 37-Time

**Descripcion:** El puerto 37, Time Protocol, puede estar en uso por equipos heredados y ha sido reemplazado en gran medida por el uso del puerto 123 para Network Time Protocol (NTP). NTP en el puerto 123 ofrece mejores capacidades de manejo de errores, lo que reduce la probabilidad de errores inesperados.

**Protocolo:** Time Protocol

**Puerto alternativo seguro:** 123-NTP

**Protocolo:** Network Time Protocol

### 53-DNS

**Puerto inseguro:** 53-DNS

**Descripcion:** El puerto 53, Domain Name Service (DNS), todavia se usa ampliamente. Sin embargo, usar DNS over TLS (DoT) en el puerto 853 protege la informacion DNS contra modificaciones en transito.

**Protocolo:** Domain Name Service

**Puerto alternativo seguro:** 853-DoT

**Protocolo:** DNS over TLS (DoT)

### 80-HTTP

**Puerto inseguro:** 80-HTTP

**Descripcion:** El puerto 80, HyperText Transfer Protocol (HTTP), es la base de casi todo el trafico de navegadores web en internet. La informacion enviada mediante HTTP no esta cifrada y es susceptible a ataques de sniffing. Se prefiere HTTPS con cifrado TLS, ya que protege los datos en transito entre el servidor y el navegador. Observa que esto a menudo se anota como SSL/TLS. Secure Sockets Layer (SSL) ha sido comprometido y ya no se considera seguro. Ahora se recomienda que servidores web y clientes usen Transport Layer Security (TLS) 1.3 o superior para la mejor proteccion.

**Protocolo:** HyperText Transfer Protocol

**Puerto alternativo seguro:** 443-HTTPS

**Protocolo:** HyperText Transfer Protocol (SSL/TLS)

### 143-IMAP

**Puerto inseguro:** 143-IMAP

**Descripcion:** El puerto 143, Internet Message Access Protocol (IMAP), es un protocolo usado para recuperar correos electronicos. El trafico IMAP en el puerto 143 no esta cifrado y es susceptible a sniffing de red. La alternativa segura es usar el puerto 993 para IMAP, que agrega seguridad SSL/TLS para cifrar los datos entre el cliente de correo y el servidor de correo.

**Protocolo:** Internet Message Access Protocol

**Puerto alternativo seguro:** 993-IMAP

**Protocolo:** IMAP para SSL/TLS

### 161/162-SNMP

**Puerto inseguro:** 161/162-SNMP

**Descripcion:** Los puertos 161 y 162, Simple Network Management Protocol, se usan comunmente para enviar y recibir datos utilizados para gestionar dispositivos de infraestructura. Debido a que estos mensajes suelen incluir informacion sensible, se recomienda usar SNMP version 2 o 3 (abreviado SNMPv2 o SNMPv3) para incluir cifrado y funciones de seguridad adicionales. A diferencia de muchos otros casos tratados aqui, todas las versiones de SNMP usan los mismos puertos, por lo que no existe un emparejamiento definitivo seguro e inseguro. Se necesita contexto adicional para determinar si la informacion en los puertos 161 y 162 esta protegida.

**Protocolo:** Simple Network Management Protocol

**Puerto alternativo seguro:** 161/162-SNMP

**Protocolo:** SNMPv3

### 445-SMB

**Puerto inseguro:** 445-SMB

**Descripcion:** El puerto 445, Server Message Block (SMB), es usado por muchas versiones de Windows para acceder a archivos a traves de la red. Los archivos se transmiten sin cifrar, y muchas vulnerabilidades son bien conocidas. Por lo tanto, se recomienda que el trafico en el puerto 445 no pueda pasar a traves de un firewall en el perimetro de red. Una alternativa mas segura es el puerto 2049, Network File System (NFS). Aunque NFS puede usar cifrado, tambien se recomienda no permitir NFS a traves de firewalls.

**Protocolo:** Server Message Block

**Puerto alternativo seguro:** 2049-NFS

**Protocolo:** Network File System

### 389-LDAP

**Puerto inseguro:** 389-LDAP

**Descripcion:** El puerto 389, Lightweight Directory Access Protocol (LDAP), se usa para comunicar informacion de directorio desde servidores a clientes. Esto puede ser una libreta de direcciones para correo electronico o nombres de usuario para inicios de sesion. El protocolo LDAP tambien permite actualizar registros en el directorio, introduciendo riesgo adicional. Como LDAP no esta cifrado, es susceptible a ataques de sniffing y manipulacion. Lightweight Directory Access Protocol Secure (LDAPS) agrega seguridad SSL/TLS para proteger la informacion mientras esta en transito.

**Protocolo:** Lightweight Directory Access Protocol

**Puerto alternativo seguro:** 636-LDAPS

**Protocolo:** Lightweight Directory Access Protocol Secure
