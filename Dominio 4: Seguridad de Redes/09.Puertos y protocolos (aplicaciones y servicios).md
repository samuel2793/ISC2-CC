# Puertos y protocolos (aplicaciones/servicios)

**Hay puertos fisicos a los que conectas cables y puertos logicos que determinan hacia donde van los datos/trafico.**

### Puertos fisicos

Los puertos fisicos son los puertos en routers, switches, servidores, computadoras, etc., a los que conectas cables (por ejemplo, cables de fibra optica, cables Cat5) para crear una red.

### Puertos logicos

**Cuando se establece una conexion de comunicacion entre dos sistemas, se hace usando puertos. Un puerto logico (tambien llamado socket) es poco mas que un numero de direccion que ambos extremos del enlace de comunicacion acuerdan usar al transferir datos.**

Los puertos permiten que una sola direccion IP soporte multiples comunicaciones simultaneas, cada una usando un numero de puerto diferente. En la capa de aplicacion del modelo TCP/IP, que incluye las capas de sesion, presentacion y aplicacion del modelo OSI, residen numerosos protocolos especificos de aplicaciones o servicios. Los tipos de datos se mapean usando numeros de puerto asociados con servicios. Por ejemplo, el trafico web (o HTTP) es el puerto 80. El trafico web seguro (o HTTPS) es el puerto 443. La Tabla 5.4 destaca algunos de estos protocolos y sus puertos habituales o asignados. Observa que, en varios casos, un servicio o protocolo puede tener dos puertos asignados, uno seguro y otro no seguro.

En caso de duda, los sistemas deben implementarse usando la version mas segura de un protocolo y sus servicios.

- Puertos bien conocidos (0-1023): estos puertos estan relacionados con los protocolos comunes que estan en el nucleo del modelo Transport Control Protocol/Internet Protocol (TCP/IP), Domain Name Service (DNS), Simple Mail Transfer Protocol (SMTP), etc.
- Puertos registrados (1024-49151): estos puertos suelen asociarse con aplicaciones propietarias de proveedores y desarrolladores. Aunque son aprobados oficialmente por Internet Assigned Numbers Authority (IANA), en la practica muchos proveedores simplemente implementan un puerto de su eleccion. Algunos ejemplos incluyen autenticacion Remote Authentication Dial-In User Service (RADIUS) (1812), Microsoft SQL Server (1433/1434) y Docker REST API (2375/2376).
- Puertos dinamicos o privados (49152-65535): cada vez que se solicita un servicio asociado con puertos bien conocidos o registrados, esos servicios responderan con un puerto dinamico que se usa para esa sesion y luego se libera.
