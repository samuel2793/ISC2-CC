# Caracteristicas y responsabilidad compartida en la nube

[!BADGE: NUEVO 2026 - objetivo 4.3]

La computacion en la nube proporciona recursos configurables como servicios. El cliente y el proveedor comparten responsabilidades de seguridad, pero la distribucion concreta cambia segun el modelo contratado.

### Caracteristicas esenciales

- Autoservicio bajo demanda: el cliente puede aprovisionar recursos cuando los necesita sin intervencion manual continua del proveedor.
- Acceso amplio a la red: las capacidades estan disponibles mediante red y mecanismos estandar.
- Agrupacion de recursos: el proveedor comparte infraestructura entre clientes manteniendo separacion logica.
- Elasticidad rapida: los recursos pueden crecer o reducirse con rapidez segun la demanda.
- Servicio medido: el consumo se monitoriza y se factura o asigna conforme al uso.

Elasticidad no es exactamente lo mismo que escalabilidad. Escalar aumenta o reduce capacidad; elasticidad ajusta esa capacidad de manera dinamica para responder a la demanda.

### Modelos de servicio

- IaaS: el proveedor gestiona infraestructura fisica y virtualizacion; el cliente suele gestionar sistemas operativos, configuraciones, aplicaciones, identidades y datos.
- PaaS: el proveedor gestiona tambien sistema operativo y plataforma; el cliente gestiona sus aplicaciones, identidades, configuraciones disponibles y datos.
- SaaS: el proveedor opera la aplicacion y la infraestructura; el cliente sigue siendo responsable de usuarios, permisos, configuracion del servicio, uso y datos dentro de su control.

Las fronteras exactas dependen del contrato y del servicio. SaaS no transfiere toda la responsabilidad al proveedor.

### Modelos de despliegue

- Publica: recursos ofrecidos por un proveedor a multiples clientes.
- Privada: infraestructura dedicada a una sola organizacion.
- Comunitaria: compartida por organizaciones con requisitos comunes.
- Hibrida: integra dos o mas entornos distintos con portabilidad o coordinacion entre ellos.

### Modelo de seguridad compartida

El proveedor suele proteger la seguridad **de** la nube: instalaciones, hardware, infraestructura y componentes que opera. El cliente protege la seguridad **en** la nube: datos, identidades, accesos, configuraciones y cargas que controla.

El cliente debe conocer:

- Que configura y que administra el proveedor.
- Quien parchea cada capa.
- Como se cifran y eliminan los datos.
- Que logs y evidencias estan disponibles.
- Donde se almacenan y procesan los datos.
- Como se notifican incidentes y se recupera el servicio.
- Como se exportan los datos y finaliza la relacion.

### Riesgos frecuentes

Las configuraciones publicas accidentales, permisos excesivos, secretos expuestos, cuentas sin MFA, recursos olvidados y falta de logs son responsabilidades que el cliente no puede delegar simplemente por utilizar cloud.

### Claves para el examen

- La responsabilidad siempre es compartida; su distribucion cambia entre IaaS, PaaS y SaaS.
- El proveedor protege la infraestructura que opera; el cliente conserva responsabilidad sobre datos e identidades.
- Nube publica no significa que los datos deban ser publicos.
- Elasticidad, agrupacion y servicio medido son caracteristicas, no modelos de servicio.
