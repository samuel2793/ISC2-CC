# Profundizacion en DMZ (Demilitarized Zone)

Un servidor web front-end podria estar en la DMZ, pero podria recuperar datos de un servidor de base de datos que esta al otro lado del firewall. Por ejemplo, puedes tener una red donde gestionas informacion personal de tus clientes y, aunque los datos esten cifrados u ofuscados mediante criptografia, debes asegurarte de que la red este completamente segregada del resto de la red, con switches seguros a los que solo tenga acceso una persona autorizada.

Solo el personal autorizado puede controlar la configuracion del firewall y controlar el trafico entre el servidor web y la red interna. Por ejemplo, en un hospital o consultorio medico, tendrias una red segregada para la informacion de pacientes y facturacion, y al otro lado estarian los registros medicos electronicos. Si usan una aplicacion basada en web para servicios de registros medicos, tendrian una zona desmilitarizada o areas segmentadas, y quizas incluso detras del firewall tendrian su propio servidor especifico para proteger la informacion critica y mantenerla segregada.

Vale la pena senalar en este punto que, aunque este curso no explorara los detalles, algunas redes usan un Web Application Firewall (WAF) en lugar de una red DMZ. El WAF tiene una conexion interna y una externa, como un firewall tradicional, con el trafico externo filtrado por el firewall tradicional o de proxima generacion. Primero, monitorea todo el trafico, cifrado o no, desde el exterior en busca de comportamiento malicioso antes de pasar comandos a un servidor web que puede ser interno a la red.
