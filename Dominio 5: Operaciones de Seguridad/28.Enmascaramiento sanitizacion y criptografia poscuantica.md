# Enmascaramiento, sanitizacion y criptografia poscuantica

[!BADGE: NUEVO 2026 - objetivo 5.1]

La proteccion de datos combina clasificacion, etiquetado, controles de acceso, transformacion, cifrado, retencion y eliminacion. La tecnica adecuada depende de la sensibilidad, el uso previsto, el soporte y las obligaciones aplicables.

### Enmascaramiento de datos

El **data masking** sustituye o oculta valores sensibles para que puedan utilizarse sin exponer el dato completo. Por ejemplo, una aplicacion puede mostrar solamente los ultimos cuatro digitos de una tarjeta o reemplazar nombres reales por valores ficticios en un entorno de pruebas.

- Enmascaramiento estatico: crea una copia transformada de los datos.
- Enmascaramiento dinamico: oculta valores al mostrarlos, segun la identidad o el contexto.

El enmascaramiento reduce exposicion, pero no siempre hace anonimos los datos. Si existe informacion adicional que permite identificar a una persona, sigue habiendo riesgo de reidentificacion.

### Tokenizacion y seudonimizacion

La tokenizacion reemplaza un dato sensible por un token y conserva la relacion en un sistema protegido. La seudonimizacion sustituye identificadores, pero puede permitir reidentificacion mediante informacion separada.

Estas tecnicas no son equivalentes al cifrado. El cifrado transforma datos mediante un algoritmo y una clave; la tokenizacion utiliza un valor sustituto.

### Sanitizacion

La **sanitizacion de medios** elimina el acceso a datos de forma apropiada para la tecnologia y el riesgo. Puede aplicarse mediante:

- Clear: elimina datos utilizando funciones logicas apropiadas para reutilizacion dentro de un nivel aceptable de proteccion.
- Purge: dificulta la recuperacion incluso con tecnicas avanzadas y permite, cuando la politica lo autoriza, reutilizar el medio con mayor confianza.
- Destroy: hace que el medio quede inutilizable y que la recuperacion resulte inviable.

El metodo debe adaptarse al soporte. Las tecnicas adecuadas para discos magneticos pueden no funcionar igual en SSD, memoria flash, dispositivos moviles o almacenamiento cloud. Debe verificarse el resultado y conservarse evidencia cuando corresponda.

Eliminar un archivo o formatear rapidamente un dispositivo no garantiza sanitizacion. Antes de desechar, devolver, reasignar o vender un activo deben seguirse politica, procedimientos y requisitos del fabricante o proveedor.

### Criptografia resistente a la computacion cuantica

Los ordenadores cuanticos suficientemente potentes podrian debilitar algoritmos asimetricos ampliamente utilizados. La **criptografia poscuantica** utiliza algoritmos diseñados para resistir ataques de ordenadores clasicos y cuanticos.

La preparacion incluye inventariar algoritmos, certificados, claves, protocolos y datos que necesitan confidencialidad a largo plazo; seguir estandares aprobados; probar interoperabilidad y planificar una migracion con agilidad criptografica.

La amenaza conocida como harvest now, decrypt later consiste en recopilar hoy datos cifrados para intentar descifrarlos en el futuro. Es especialmente relevante para informacion que debe permanecer secreta durante muchos años.

No deben inventarse algoritmos ni migrarse sistemas criticos sin pruebas. La organizacion debe utilizar implementaciones y estandares reconocidos y mantener capacidad para cambiar algoritmos.

### Claves para el examen

- Masking oculta valores; tokenizacion los sustituye; cifrado usa algoritmo y clave.
- Seudonimizacion puede ser reversible mediante informacion adicional.
- Sanitizacion depende del medio, riesgo y destino del activo.
- Borrar un archivo no equivale a sanitizar el soporte.
- La criptografia poscuantica exige inventario, planificación y agilidad criptografica.
