# Personal autorizado frente a no autorizado

**A los sujetos se les concede acceso autorizado a los objetos despues de haber sido autenticados. La autenticacion confirma la identidad del sujeto. Una vez que un sujeto ha sido autenticado, el sistema verifica su autorizacion para ver si tiene permitido completar la accion que intenta realizar.**

Esto normalmente se hace mediante una matriz de seguridad a la que accede el sistema que controla el acceso, basada en niveles preaprobados. Por ejemplo, cuando una persona presenta una credencial de ID en la puerta del centro de datos, el sistema verifica el numero de ID, lo compara con una matriz de seguridad dentro del sistema y desbloquea la puerta si el ID esta autorizado. Si el ID no esta autorizado para desbloquear la puerta, permanecera cerrada. En otro ejemplo, un usuario intenta eliminar un archivo. El sistema de archivos verifica los permisos para ver si el usuario esta autorizado a eliminar el archivo. Si el usuario esta autorizado, el archivo se elimina. Si el usuario no esta autorizado, se muestra un mensaje de error y el archivo queda intacto.

### Como se aprovisionan los usuarios

Otras situaciones que requieren aprovisionar nuevas cuentas de usuario o cambiar privilegios incluyen:
- **Un nuevo empleado**
Cuando se contrata a un nuevo empleado, el gerente de contratacion envia una solicitud al administrador de seguridad para crear un nuevo ID de usuario. Esta solicitud autoriza la creacion del nuevo ID y proporciona instrucciones sobre los niveles de acceso adecuados. La politica de la compania puede requerir autorizacion adicional para permisos elevados.
- **Cambio de puesto**
Cuando un empleado ha sido promovido, sus permisos y derechos de acceso pueden cambiar segun lo definido por el nuevo rol, que determinara cualquier privilegio agregado y actualizacion de acceso. Al mismo tiempo, se eliminara cualquier acceso que ya no sea necesario en el nuevo trabajo.
- **Separacion laboral**
Cuando los empleados dejan la compania, dependiendo de la politica y los procedimientos de la compania, sus cuentas deben deshabilitarse despues de la fecha y hora de terminacion. Se recomienda que las cuentas se deshabiliten durante un periodo antes de eliminarlas para preservar la integridad de cualquier rastro de auditoria o archivo que pueda pertenecer al usuario. Como la cuenta ya no se usara, debe retirarse de cualquier rol de seguridad o perfil de acceso adicional. Esto protege a la compania, ya que el empleado separado no puede acceder a datos de la compania despues de su salida; tambien protege al empleado porque su cuenta no puede ser usada por otros para acceder a datos.

**NOTA:**
Al contratar o cambiar roles, una buena practica es no copiar perfiles de usuario a nuevos usuarios porque esto promueve la acumulacion progresiva de permisos o privilegios. Por ejemplo, si a un empleado se le concede acceso adicional para completar una tarea y ese acceso no se elimina cuando la tarea se completa, y luego se copia el perfil de ese usuario para crear un nuevo ID de usuario, el nuevo ID se crea con mas permisos de los necesarios para completar sus funciones. Se recomienda establecer roles estandar y crear nuevos usuarios basandose en esos estandares, en lugar de basarse en un usuario real.
